# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A pure-Bash installer that gets the Apple FaceTime HD camera (Broadcom BCM1570, PCI `14e4:1570`) working on 2013–2015 Intel MacBooks under Ubuntu 22.04/24.04/26.04 and Fedora 44. It builds the `facetimehd` driver via DKMS, extracts the Apple firmware, and optionally makes sure `mbpfan` is installed and running so the fans stop throttling. It configures no power management at all - see "Power management" below. The internal keyboard needs nothing from this project: `hid_apple` ships in the kernel on every supported distribution and loads itself.

The driver built by this project is [src/facetimehd/](src/facetimehd/), a
maintained fork of `patjak/facetimehd` commit `364b1c663583`, with its changes
documented in [src/facetimehd/DOWNSTREAM.md](src/facetimehd/DOWNSTREAM.md).
[driver-patches/](driver-patches/) holds that same change set as a generated,
numbered patch series against the upstream tree - useful for review or for
proposing individual changes upstream. It is an output of `DOWNSTREAM.md`,
not an input to anything: nothing in `scripts/`, `tests/` or CI reads it, and
it is regenerated by hand when the fork moves rather than kept in sync
automatically.

## Commands

```bash
# Lint (exactly what CI runs - see .github/workflows/ci.yml)
shellcheck -x --source-path=SCRIPTDIR \
    setup.sh \
    scripts/install.sh scripts/uninstall.sh scripts/macbook-tune.sh scripts/extract-firmware.sh \
    tests/build-driver.sh tests/smoke-capture.sh
# scripts/lib/common.sh is only sourced, never listed directly - shellcheck -x
# follows it from whatever sources it. tests/hw-validate.sh needs a MacBook to
# run and is not part of the CI lint job either; shellcheck it by hand after
# editing it.

# Compile src/facetimehd against every headers tree present
./tests/build-driver.sh
./tests/build-driver.sh 7.0.0-14-generic      # one kernel only
KDIR=/path/to/headers ./tests/build-driver.sh # an unpacked headers package
CC=gcc-14 ./tests/build-driver.sh             # pin the compiler
LLVM=1 W=1 WERROR=1 ./tests/build-driver.sh   # strict Clang build
SPARSE=1 W=1 ./tests/build-driver.sh           # Sparse semantic checks

# Exercise the installed driver on real hardware (needs a MacBook + v4l-utils)
sudo ./tests/smoke-capture.sh                 # leaves the module loaded
sudo ./tests/smoke-capture.sh --unload        # remove it afterwards
./tests/smoke-capture.sh --no-load            # module already loaded, no root

# Validate the things only hardware can confirm - one section per open item in
# src/facetimehd/DOWNSTREAM.md "Hardware validation status"
sudo ./tests/hw-validate.sh                   # all but the reboot test
sudo ./tests/hw-validate.sh --only probe,timing
sudo ./tests/hw-validate.sh --skip suspend    # laptop in use, or headless
sudo ./tests/hw-validate.sh --reboot          # reboots; re-run after to read the verdict

# Firmware extraction on its own (install.sh calls this; --no-install needs no root)
./scripts/extract-firmware.sh --no-install
sudo ./scripts/extract-firmware.sh [--dest DIR] [-x DRIVER_FILE] [-i]

# Sensor calibration (.dat) files - a separate Apple download, needs unar
sudo ./scripts/extract-firmware.sh --calibration-only
sudo ./scripts/extract-firmware.sh --calibration-only --sys /path/AppleCamera.sys

# Single entry point: asks which of the below to run, then runs it
sudo ./setup.sh [-y]

# Install / uninstall (require root)
sudo ./scripts/install.sh [-y|--force|--skip-firmware|--skip-hw-check]
sudo ./scripts/uninstall.sh [--keep-tuning]

# Make sure mbpfan is installed and running (requires root)
# Not configured - it ships a sane fan curve - this just installs/enables it.
sudo ./scripts/macbook-tune.sh [--revert|--skip-fan]
```

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs shellcheck, an executable-bit check on `setup.sh`, `scripts/*.sh` and `tests/*.sh`, the driver build across Ubuntu 22.04/24.04/26.04 + Fedora 44, and strict Clang and Sparse analysis — on every push and weekly on a schedule. The weekly run is the point: it catches kernel breakage with nobody touching the repo.

Fedora is in the matrix because it carries the newest kernel of anything tested, so kernel API churn lands there first. The Fedora job passes `KDIR=/usr/src/kernels/<ver>` to `build-driver.sh`, because `kernel-devel` unpacks there and a container has no `/lib/modules/<ver>/build` symlink to follow.

## Architecture

**[setup.sh](setup.sh) is a menu, not a place for logic.** It asks two yes/no
questions (driver? fan support?) and calls `scripts/install.sh` and/or
`scripts/macbook-tune.sh` with `-y` if it got one itself. It has no options of
its own beyond `-y`/`--help` and does not know about `--skip-firmware`,
`--revert`, or anything else the scripts it calls support - those are reached
by running that script directly. Keep it that way: logic belongs in the
script that owns the thing being configured, not in the entry point in front
of it.

**The maintained driver source is included.** The fork lives under
[src/facetimehd/](src/facetimehd/) and installing does not fetch source from
GitHub. The one networked project step is firmware extraction from Apple's
servers, because that firmware cannot legally be redistributed.

**Sensor calibration is a second, independent download.** The `NNNN_01XX.dat`
set files fix the camera's colours and exist *only* in the Windows Boot Camp
driver — the OS X kext does not carry them, so the firmware download cannot
supply them. `extract-firmware.sh` range-fetches just the
`AppleCamera64.exe` member out of the 542 MB `bootcamp5.1.5769.zip` (~1.2 MB),
inflates it with a synthesised gzip header rather than a zip tool, unpacks the
solid RAR with `unar`, and carves the four files at offsets keyed by the
SHA-256 of `AppleCamera.sys` — which is the *same* hash table the firmware path
already uses, because it is the same file. Each carved file is SHA-256 verified,
so a wrong offset installs nothing. `unrar-free` cannot read solid RAR3 and is
not a substitute. The camera works without all of this, so `install.sh` treats
every failure here as a warning.

**Firmware extraction is ours** ([scripts/extract-firmware.sh](scripts/extract-firmware.sh)). It is derived from `patjak/facetimehd-firmware`, which died in 2020, and is maintained here under GPL-2.0-only. It downloads a byte range of an Apple-hosted OS X 10.11.5 update, carves the firmware out of the `AppleCameraInterface` kext, and SHA-256-verifies both the kext and the image. Only firmware 1.43.0 actually works.

**Version derivation** ([scripts/install.sh](scripts/install.sh)): `PACKAGE_VERSION` is read out of `src/facetimehd/dkms.conf`. A fingerprint of `src/facetimehd/**/*.{c,h}` + `Makefile` is appended as `+d<hash>`, then the staged copy under `/usr/src/` gets its `dkms.conf` rewritten to match.

**Idempotency**: `install.sh` copies `src/facetimehd/` to a temporary tree, diffs that against `/usr/src/facetimehd-<version>` (excluding `dkms.conf`), and skips the rebuild when they match and DKMS reports installed. `uninstall.sh` discovers every registered DKMS version rather than assuming one.

**Shared shell layer**: [scripts/lib/common.sh](scripts/lib/common.sh) is sourced, never executed — output helpers (`info`/`step`/`warn`/`error`/`die`/`ok`/`bad`, NO_COLOR-aware), `require_root`/`have`/`require_cmds`/`confirm` (honours `ASSUME_YES`), `detect_os`/`is_debian_like`/`is_rpm_like`, the package layer below, `has_facetimehd_hardware`, `firmware_root`, systemd probes. New scripts source it and get shellchecked with `-x --source-path=SCRIPTDIR`.

**Package abstraction**: `pkg_manager`/`pkg_refresh`/`pkg_install`/`pkg_installed`/`pkg_available` wrap apt and dnf. They abstract the *verbs* only — package names differ per family and stay in the calling script, because that is where the reason for each name lives. `pkg_available` exists to tell "not installed yet" apart from "not packaged for this distro at all"; that distinction is what lets `macbook-tune.sh` exit cleanly on a derivative with no mbpfan package instead of dying on a package-manager error.

**Fan support is deliberately its own script** ([scripts/macbook-tune.sh](scripts/macbook-tune.sh)), not part of `install.sh`. `mbpfan` is not coupled to the camera — the camera works without it, and it works on a Mac with no camera driver — so the camera installer does not change unrelated system behaviour by default; it only points at the script. The script installs and enables `mbpfan`; it does not configure it, because its own fan curve is reasonable for this hardware. State (whether it enabled `mbpfan.service` itself) lives under `/var/lib/facetimehd/`, so `--revert` only disables the service if this script was the one that turned it on. `uninstall.sh` delegates that to `macbook-tune.sh --revert` rather than reimplementing it. `hid_apple` needs nothing at all: it ships in the kernel and loads itself.

**Power management is not this project's job.** The driver implements its own runtime PM (see [src/facetimehd/DOWNSTREAM.md](src/facetimehd/DOWNSTREAM.md), "Power management and lifecycle"): real `dev_pm_ops`, a `runtime_pm` module parameter that defaults on, with `facetimehd.runtime_pm=0` as the escape hatch. Every supported distribution already ships a power daemon that never touches PCI runtime PM, USB autosuspend or PCIe ASPM (`power-profiles-daemon` on Ubuntu, TuneD on Fedora), so there is nothing left for this project to configure.

## Deliberate decisions

There used to be a separate `docs/` tree (`AUDIT-2026-08.md`, `POWER.md`,
`TROUBLESHOOTING.md`); it was folded into `README.md` and
`src/facetimehd/DOWNSTREAM.md` and no longer exists. A few in-repo comments
and `install.sh` warning strings still point at those paths — treat any
`docs/*.md` reference you find as pointing at the README's "Troubleshooting
and support" section instead, and feel free to fix the stale path when you're
already touching that file. The reasoning that used to live in the audit doc
is folded into this section instead; read it before "fixing" any of these:

- **No top-level `dkms.conf`.** The authoritative one is `src/facetimehd/dkms.conf`; a second copy only drifts.
- **The firmware checksum tables live in one place** — [scripts/extract-firmware.sh](scripts/extract-firmware.sh). They were upstream's; they are now ours to maintain. Do not copy them into `install.sh` or the docs.
- **No driver version or kernel version anywhere in the scripts.**
- **A change to `src/facetimehd/` is not done until `DOWNSTREAM.md` says why.** The fork has no patch headers to carry that reasoning instead, so this is the review record for its changes. `driver-patches/` is a generated view of that same record, not a second place to explain anything.
- **This project configures no power management, and does not configure mbpfan.** See the "Fan support" and "Power management" paragraphs above for why `macbook-tune.sh` only installs and enables rather than writing config, and why nothing here touches PCI runtime PM, USB autosuspend, ASPM or a power-profile daemon. Do not reintroduce a fan curve, a `hid_apple` modprobe drop-in, or a TLP/power-profile drop-in without a concrete problem the upstream defaults don't solve.
- **`hid_apple` is not this project's concern at all any more.** It ships in the kernel on every supported distribution and loads itself; there is nothing to install, check, or configure, so `macbook-tune.sh` no longer touches it.
- **`facetimehd.runtime_pm=0` is the escape hatch for the driver's own runtime PM.** There is no denylist-side equivalent any more — nothing this project installs manages PCI runtime PM from the outside.
- **The DDR/PLL bring-up messages are `dev_dbg`, not `dev_info`** — and the same goes for `FWMSG`, the firmware's own console. They read like once-per-boot banners, but runtime PM re-runs `fthd_hw_init()` on *every* resume, so at `dev_info` they wrap a default kernel ring buffer in a minute or two and evict everything else, including the driver's own suspend records. Probe prints one `dev_info` summary line instead; `dyndbg=+p` brings the detail back. Failure messages were moved the other way, `dev_info` → `dev_err`.
- **Debugfs is created in `probe()` and destroyed in `remove()`, never across a suspend.** `debugfs_create_devm_seqfile()` is devm-managed, and runtime PM makes a suspend/resume cycle happen every few idle seconds, so tearing the tree down and rebuilding it each time leaks a devres entry. The accessors take a runtime-PM reference instead — reading one powers the camera up.
- **The whole project is GPL-2.0-only.** `scripts/` was MIT until 2026-08, when absorbing the GPL-2.0-only firmware extractor into `scripts/extract-firmware.sh` required relicensing the lot. Derived code must keep its upstream attribution header — do not quietly reword provenance away.
- **`diffutils` is in the RPM dependency list on purpose.** It is Essential on Debian and so never listed there, but a minimal Fedora has no `diff` at all — and the rebuild-skip in `install.sh` is a `diff -rq` whose failure is swallowed. Without it the installer silently loses idempotency and rebuilds every run.
- **The kernel build tree is tested with `-d /lib/modules/<kver>/build`, not `-e` or `-L`.** On Fedora that path is a symlink shipped by `kernel-modules-core` pointing into `/usr/src/kernels/<kver>`, which only exists once `kernel-devel` is installed. The normal "headers missing" state there is a *dangling* symlink, so only a test that resolves it is correct.

## Conventions

- Scripts are `#!/usr/bin/env bash` with `set -euo pipefail`, must be executable, and must pass shellcheck.
- Everything must be idempotent, reversible, and leave the system bootable if interrupted.
- Commit messages: `type: brief description` (`fix:`, `feat:`, `docs:`, `refactor:`, `test:`, `chore:`).
